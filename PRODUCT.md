# Product

## Register

product

## Users

People and administrators using the existing New API console to manage model access, API keys, limits, and request history. Delegated account members must see the resources they are authorized to use.

## Product Purpose

Keep the existing model gateway console familiar while making delegated resource access and attribution accurate. Preserve working key management, diagnostics, quotas, and historical usage.

## Brand Personality

Practical, clear, familiar. Preserve New API and QuantumNous identity and the established console visual language.

## Anti-references

A replacement dashboard, a new visual theme, decorative product cards, duplicate controls, and explanatory copy used in place of explicit permissions.

## Design Principles

- Reuse the existing account boundary, forms, tables, dialogs, formatting, and query patterns.
- Show the current account, resource subject, and available actions using established controls.
- Keep create, limit, revoke, and historical read behavior consistent across views.
- Treat server permissions as authority and preserve the distinction between a creator and a resource user.
- Retain native diagnostics and accurate amounts without exposing internal identities or credentials.

## Accessibility & Inclusion

Follow the repository WCAG 2.1 AA requirements, keyboard and focus conventions, responsive layout, seven existing locales, reduced-motion preferences, and native light/dark themes.

This context is derived from README.md, AGENTS.md, web/AGENTS.md, web/components.json, and the existing key/account components. It does not introduce a new design system.
